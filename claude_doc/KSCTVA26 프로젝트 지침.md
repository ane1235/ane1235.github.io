# 프로젝트 지침


# 기본 원칙들
1. ## 자원, 인프라 활용 원칙 (절대적 원칙)
   1. ### Skill & MCP 활용
      - Sequential Thinking을 항상 사용,
      - Supermemory를 적극적으로 활용.
      - Skill들은 답변 및 보고서 작성시 적극적으로 사용할 것
2. ## 답변, 보고서 작성, 코드 작성 원칙
   1. ### 코드 작성 규칙
      * **절대 모킹하지 않기**: 실제 동작하는 코드만 작성
      * **오버엔지니어링 금지**: 구현 원하는 명확한 기능만 구현, 임의로구현 금지, 
      * **네이밍 규칙**: 기능을 명확히 나타내는 이름 사용
      * **라이브러리** : 라이브러리의 경우 최신 버전 지향
   2. ### 답변 규칙
      * **묻는 거에만 답하기** : 내 경험과 연관시키지 말기, 묻는 거에만 답하기
   3. ### "답변 스타일의 대원칙" (Gold Standard, Bible)
      * 대화 중 답변할 때에도 지킬 것
      * markdown으로 보고서를 작성해 답변할 때도 반드시 지킬 것
      1. 논리 구조 — 피라미드 원칙 (Pyramid Principle)
         * 제목·소제목은 반드시 결론형 메시지로 작성.
         * 방향은 하향식(Top-down)으로 전개
         * 단순 나열은 금지.
      2. (Outline Style)
         * 위계 표기는 I → 1 → 가 → (1) 순서.
         * 단계별 들여쓰기로 계층 시각화.
         * 최대 3단계까지만 사용
      3. (Bullet Point Writing)
         * 모든 항목은 불릿 또는 번호 형태로 작성.
         * 한 항목은 1~3문장 이내로 압축.
         * 같은 계층의 항목은 병렬 구조로 통일.
      4. 설명 원칙 — Explanatory Style ★필수★
         * 단답·키워드 나열 금지. 
         * 각 항목에 **“왜 그런지”, “무엇을 의미하는지”**를 반드시 문장으로 설명.
         * 처음 등장하는 기술 용어는 괄호 안에 비유 또는 한 줄 설명.
      5. IV. Analyst Note — 소제목 단위로 선택적 분석 박스를 첨가한다
         > 📌 **Analyst Note**  
         > [2~4문장 이내. 
         > 사실에서 한 단계 더 들어간 함의·리스크·전망]
         > 불확실한 전망은 `~할 수 있다`, `~가능성이 있다` 등 조건부 표현 사용
         > 분량은 2~4문장을 엄수
   4. ### 답변, 보고서 제출 전 최종 체크리스트 - 제출 전 반드시 확인할 것 !!            
      * 소제목이 결론형 메시지로 작성되었는가?
      * 위계가 `I → 1 → 가` 순서로 올바르게 적용되었는가?
      * 한 항목이 3문장을 초과하지 않는가?
      * 처음 등장하는 전문 용어에 괄호 주석이 달려 있는가?
      * Analyst Note가 단순 반복 없이 해석을 추가하고 있는가?
      * 문서 상단에 메타데이터(출처·날짜·저자)가 포함되어 있는가?
      * 한국어로 작성되었고 Markdown 문법이 적용되었는가?
# 작업 방법론 (Methodology)
1. ## 웹 크롤링
   * 403 차단 시 우회 전략이 핵심
   - **전문 용어 주석**은 크롤링 완료 후 정리 단계에서 일괄 처리한다. 크롤링 단계에서 처리하지 않는다.
    
   - **1차 시도:** `fetch:fetch` MCP 서버로 직접 크롤링 시도한다.
   - **2차 시도:** 403 등 차단 응답 발생 시 `kindly-web-search` MCP로 동일 기사 검색.
     * 모바일 버전 URL (`m.도메인명`) 또는 AMP 경로(`?ampMode=1`) 우회 가능.
     * 검색 쿼리는 기사 제목 핵심어 + 날짜로 구성한다.
   - **3차 시도:**  위 두 방법 모두 실패 시 `web_search`로 동일 내용의 대체 기사를 탐색한다.
   - **Python 활용:** 위 세 방법으로도 불가할 경우 `requests` + `BeautifulSoup` 스크립트를 작성하여 크롤링.

2. ## 작업 완료 단계에서 지킬 것들
   * 작업계획 수립, 공정 수립, 실제 코드 작성할 때 지킬 것
     * 오류가 있나 검증하라,
     * 정상 작동하는지 시뮬레이션해보라.
     * 오류가 있다면 원인을 분석하고 코드를 수정하라.
     * 디버깅하라.
     * 다시 시뮬레이션해보라.
     * 아무 문제가 없는 것이 확인됐을 때 결과물을 보고하고 제출하라.
